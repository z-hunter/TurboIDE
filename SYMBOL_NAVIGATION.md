# Навигация по символам

Этот документ — актуальное описание навигации по коду в TurboIDE. План
`SETSED_PHASE2_NAVIGATION_PLAN.md` сохранён как история решения; при
расхождении с ним верен этот документ и код.

## Пользовательское поведение

Все команды находятся в **Search** и используют один временный индекс
Universal Ctags.

| Команда | Клавиша | Поведение |
| --- | --- | --- |
| Jump to symbol... | Ctrl+F2 | Переходит к единственному точному совпадению имени под курсором; иначе показывает список совпадений. Без имени показывает все символы. |
| Back from symbol | Ctrl+Shift+F2 | Возвращает к позиции перед последним успешным переходом. История живёт только в памяти и очищается при закрытии или смене проекта. |
| Word completion | Ctrl+Tab | Дополняет уже введенный префикс. Кандидаты берутся из текущего буфера и, если индекс доступен, из его символов. Несохранённый буфер не блокирует completion. |
| Class browser... | — | Сначала показывает C++ классы, структуры и union; затем — сам тип, его члены и известные родительские/дочерние типы. Enter открывает выбранное определение. |

Это навигация по тегам, а не семантический `Go to definition`: Ctags не
разрешает перегрузки по типам аргументов, макросы или тип выражения так, как
это делает компилятор. Несколько подходящих имён — штатный случай и требуют
выбора пользователя.

## Что индексируется

- Расширения: `.c`, `.h`, `.cc`, `.cpp`, `.cxx`, `.hh`, `.hpp`, `.hxx`,
  `.inl` (регистр не важен).
- При открытом проекте берутся `Project::sources`; сохранённый активный
  C/C++-файл добавляется, даже если ещё не внесён в проект.
- Без проекта индексируется сохранённый активный C/C++-файл.
- Изменённый активный файл записывается во временный снимок с тем же
  расширением. Ctags индексирует снимок, а его результаты сопоставляются с
  исходным именем файла; сохранение ради навигации не требуется.
- Безымянный несохранённый редактор индексировать нельзя: у него нет
  расширения и исходной позиции для перехода.

Индекс находится только в памяти. Перед запросом IDE сравнивает список
файлов, размеры и времена записи; любое изменение вызывает полную
перестройку. Неудачная перестройка очищает старый индекс, чтобы не показывать
устаревшие результаты. Индекс и история переходов не сохраняются в `.prj` или
`.dsk`.

## Ctags и поставка

Официальный x64 portable-пакет обязан содержать
`tools\ctags\ctags.exe` и его каталог `tools\ctags\license`. Это pinned
Universal Ctags 6.2.1, проверенный по SHA-256 на этапе CMake. Программа ищет
только эту приватную копию рядом с `turboide.exe`; `PATH` намеренно не
используется.

Обычная developer-сборка не скачивает Ctags. В ней разрешён
`TURBOIDE_CTAGS`, указывающий на проверяемый при запуске `ctags.exe`.
Portable-сборка отключает этот override. В обоих случаях до индексации
проверяется `ctags --version` и строка `Universal Ctags`.

Сборщик запускает Ctags напрямую через `CreateProcessW`, без shell. Пути к
файлам передаются через временный UTF-8 список `-L`; это защищает от лимита
длины командной строки. Формат вывода фиксирован параметрами
`--options=NONE --excmd=number --fields=+n+i+Z`. Reader принимает только
корректные записи с положительным номером строки, игнорирует псевдотеги и
сохраняет дубликаты имён.

Получить архив для portable-сборки:

```powershell
$archive = .\tools\fetch_ctags.ps1
cmake -S . -B .build\portable -G "Visual Studio 17 2022" -A x64 `
  -DTURBOIDE_BUNDLE_CTAGS=ON -DTURBOIDE_CTAGS_ARCHIVE=$archive
cmake --build .build\portable --config Release --target turboide
```

Лицензия и обязанность публиковать соответствующий исходный текст описаны в
`THIRD_PARTY_NOTICES.md` и `README.md`.

## Устройство и проверка

`src/symbol_index.cpp` отвечает только за поиск Ctags, запуск процесса и
разбор стабильного машинного вывода в `CodeSymbol {name, file, line, kind,
scope, inherits}`. UI, кэш, временный снимок и история находятся в
`src/main.cpp`; не переносите туда ещё один parser TAGS и не добавляйте LSP,
базу данных или фоновый индексатор без измеренной причины.

`tests/symbol_index_test.cpp` проверяет reader, Unicode-пути, повреждённые
записи и, если задан `TURBOIDE_CTAGS` либо рядом с тестом есть bundled Ctags,
реальный запуск на временном C++ файле. Для несовместимого инструмента
установите `TURBOIDE_CTAGS_EXPECT_FAILURE=1`.

Ручная проверка выполняется в отдельной папке в классическом `conhost.exe`:
откройте сохранённый C++ файл с несколькими одноимёнными символами, классом и
несохранённой правкой. Проверьте переход, список, Ctrl+Shift+F2, Ctrl+Tab,
Class Browser и переход из него. Затем измените или удалите файл и убедитесь,
что старый символ не остаётся в списке. Полный порядок запуска conhost дан в
`AGENTS.md`.
