# Отчёт: этап 3 — Run / User Screen

Дата: 2026-10-01. Статус: реализован.

## Что сделано

- `Ctrl+F9` собирает актуальный одиночный `.c` или `.prj`-проект и запускает EXE только после успешной сборки.
- Собранная программа работает в том же окне консоли с отдельным экранным буфером, вводом через `stdin`, выводом через `stdout`/`stderr`, собственной рабочей директорией и кодировкой аргументов Windows.
- После завершения IDE восстанавливает экран и окно редактора, активное перед Ctrl+F9; код завершения остаётся в Messages.
- Последний экран программы хранится до следующего запуска. `Alt+F5` показывает его до нажатия клавиши, затем возвращает IDE.
- Атрибуты нового экрана берутся из исходного консольного буфера (обычно серый текст на чёрном фоне), а не из синей/красной палитры Turbo Vision.
- Во время запуска Ctrl+C завершает программу, не закрывая IDE. Режим консольного ввода восстанавливается после завершения.
- `.prj` поддерживает `arg=значение`: одна строка задаёт один аргумент `argv` (значение может содержать пробелы).
- Исправлена интеграция с закреплённым Turbo Vision: её активный буфер создаётся с разрешённым совместным чтением/записью, чтобы IDE могла открыть `CONOUT$`, сохранить handle экрана и восстановить его после запуска.

## Проверка

- Release x64 IDE пересобрана через CMake/MSVC.
- Отдельный ConPTY smoke-клиент использовал тот же `runProgram`: дочерняя C-программа получила аргумент `hello world` из `.prj`, прочитала строку через `fgets`, показала вывод в своём буфере и вернула exit code 7.
- Проверено переключение на сохранённый экран и обратно по клавише. Ctrl+C завершил программу, ожидавшую ввод, а родительский тестовый процесс продолжил работу и восстановил свой экран.
- Пользователь подтвердил реальный запуск `Hello world` через Ctrl+F9 и просмотр результата через Alt+F5.
- После его замечания о красном окне сообщений и нестандартных цветах Run теперь возвращает фокус к редактору, оставляя сообщения под ним, и инициализирует цвета из исходного консольного буфера. Эти последние два изменения собраны, ждут повторной визуальной проверки.
- Сравнение пока сделано по руководству Turbo C 2.0; ручное сравнение с запущенной оригинальной IDE и проверка обоих поддерживаемых терминалов остаются желательными.
- После пользовательского отчёта о `The IDE console is unavailable` причина локализована: закрытый режим совместного доступа у внутреннего буфера Turbo Vision не позволял открыть `CONOUT$`; из-за этого запуск обрывался до создания User Screen. CMake теперь применяет идемпотентную правку к закреплённому исходнику Turbo Vision; конфигурация и Release-сборка после неё прошли. Нужно повторить проверку Ctrl+F9/Alt+F5 на собранном бинарнике.

## Дополнение: цикл сборки в стиле Borland

- Во время сборки показывается отдельное центрированное серое окно `Linking` с подсказкой `Ctrl-Break to quit`. Ctrl-Break отменяет сборку, завершая GCC, а IDE добавляет результат отмены в Messages.
- При успешной сборке без запуска окно сообщает `Success - Press Any Key`; подсказка мигает и закрывается по следующему нажатию клавиши.
- При сборке через Ctrl+F9 окно результата не задерживает запуск программы.
- Сообщения сохраняются в отдельном окне `Tools → Messages`. `Alt-F8` / `Alt-F7` переходят к следующему / предыдущему сообщению с координатами исходника.
- После сравнения с FPC IDE меню упорядочены в стиле Borland; Messages доступно в Tools (F11), Compiler messages — в Compile (F12), статусная строка показывает основные клавиши Borland. Нижняя панель Messages теперь широкая и бирюзовая.
- Debug x64 и последняя Release x64 сборки прошли. Первая попытка Release перелинковки была заблокирована работавшим `turboide.exe`; после закрытия процесса Release собрался. Ручная проверка внешнего вида и хоткеев ожидает пользователя.
