# Этап 2: сборка C-файла и проекта через GCC

Статус: **реализован и проверен сборкой/ручным smoke-проходом**, 2026-10-01. Основа: рабочий редактор этапа 1; пользователь подтвердил работу интерфейса и буфера Windows. Выбранный компилятор — x64 MinGW-w64 GCC 16.2.0 из w64devkit 2.10.0. IDE по-прежнему собирается MSVC. Результаты — в [STAGE2_REPORT.md](STAGE2_REPORT.md).

## Результат этапа

Команда `Alt+F9` компилирует текущий сохранённый `.c`, `F9` собирает открытый проект из нескольких `.c`. Ошибки и предупреждения появляются в окне сообщений с переходом к файлу и строке. В случае ошибки сборки IDE не предлагает старый EXE как свежий результат. Запуск EXE и отладка входят в этапы 3 и 4. Код этапа реализован; ручная Unicode-приёмка содержимого редактора и clipboard остаётся отдельным пунктом этапа 1.

## Правила реализации

- Перед многофайловой реализацией инициализировать локальный Git-репозиторий; `.gitignore` уже исключает каталог сборки. Это даст воспроизводимые точки отката.
- Первым работающим срезом сделать Compile текущего файла. Формат `.prj` добавить после него; один файл не требует проекта.
- Границы файлов: `src/main.cpp` владеет командами и окнами Turbo Vision; `src/build.*` — запуском GCC и результатом; `src/project.*` — чтением `.prj`. При одной реализации не создавать дополнительные слои между ними.
- Не обращаться к компилятору через PowerShell или `cmd`: `CreateProcessW`, отдельные аргументы и известный рабочий каталог.
- Не хранить путь к временно распакованному w64devkit в коде. Для первого запуска достаточно переменной `TURBOIDE_GCC` или `gcc.exe` в `PATH`; графическую настройку компилятора добавлять после проверки необходимости.
- Сохранять `-g -O0` для будущего GDB; обычная сборка и отладка используют один GCC.
- Записывать артефакт по относительному ASCII-пути. Ранее проверенный w64devkit linker не принял абсолютный Unicode-путь выхода.
- Сначала отделить процесс компилятора и результат от UI простыми структурами; не создавать универсальную систему задач и сборки.

## Приёмка

1. `Alt+F9` собирает один `.c` в каталоге с пробелом; отображаются команда, вывод, код завершения и расположение EXE.
2. После синтаксической ошибки строка GCC доступна в Messages и переносит курсор к ошибке. Старый EXE не считается результатом текущей сборки.
3. Несохранённое изменение учитывается перед сборкой; Cancel отменяет сборку без потери правок.
4. `F9` собирает `.prj` с двумя `.c`, заголовком, include-путём и define; относительные пути разрешаются от каталога проекта.
5. Отсутствующий GCC, неправильный путь в проекте и неудача записи EXE дают понятное сообщение; IDE остаётся работоспособной.
