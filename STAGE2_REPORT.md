# Отчёт: этап 2 — GCC и проекты

Дата: 2026-10-01. Статус: выполнен.

## Что сделано

- IDE запускает найденный в `PATH` GCC либо путь из `TURBOIDE_GCC` через `CreateProcessW`, без shell.
- `Alt+F9` компилирует текущий сохранённый `.c`; `F9` собирает активный проект или текущий `.c`, если проект не открыт.
- Добавлен текстовый UTF-8 формат `.prj`: повторяемые `source=`, `include=`, `define=`, `library=`; пути проекта разрешаются относительно `.prj`.
- Сборка идёт в фоне. Окно Build messages показывает результат и диагностику; Enter или двойное нажатие открывает файл и ставит курсор на позицию ошибки.
- Перед сборкой IDE предлагает сохранить изменённые исходники. Перед сборкой удаляется прежний EXE IDE; он считается актуальным лишь при нулевом коде завершения и наличии нового файла.
- Добавлена инструкция сборки и настройки GCC в `README.md`; `.turboide-build/` исключён из Git.

## Проверка

- Release x64 успешно собирается командой из `README.md` через CMake/MSVC.
- Smoke-проверка `runBuild`: одиночный файл с пробелом и кириллицей в имени собрался; проект из двух `.c` и общего `.h` собрался; ошибка компиляции дала распознанную диагностику с файлом, строкой и столбцом.
- В живом интерфейсе через ConPTY проверены открытие Unicode-имени файла, `F9` для одиночного файла, сборка `.prj`, показ ошибки и переход по ней на `2:12`; проверен выход из IDE.
- После исправления сводной строки диагностики полный путь остаётся доступен для перехода, а в узком окне списка показываются basename, позиция и сообщение.

## Границы и следующий шаг

- Запуск собранной программы, её ввод и `Alt+F5` ещё не реализованы; это этап 3 (Run/User Screen). GDB/MI — этап 4.
- Проверено Unicode-имя файла при сборке из ASCII-каталога. Пользователь ещё не проверял Unicode в редакторе/Windows clipboard; полная приёмка Unicode-содержимого, Unicode-пути рабочего каталога и вывода пользовательской программы не заявляется.
- Toolchain GCC/GDB не поставляется вместе с IDE. w64devkit linker требует ASCII-путь результата, поэтому артефакт создаётся в `.turboide-build\program.exe` относительно рабочего каталога.

## Сборка

```powershell
cmake -S . -B .build/pinned-prototype -G "Visual Studio 17 2022" -A x64
cmake --build .build/pinned-prototype --config Release --target turboide
```

Настройка компилятора: `$env:TURBOIDE_GCC = "C:\tools\w64devkit\bin\gcc.exe"`.
