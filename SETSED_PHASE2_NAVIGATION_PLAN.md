# Второй этап заимствования из SETEdit: навигация по символам

Дата: 2026-10-07. Основа — [обзор SETEdit](REFERENCE_SETSED_REVIEW.md) и
[план первого этапа](SETSED_PHASE1_PLAN.md). Цель — переход к функциям,
типам и другим определениям в файлах проекта, возврат после перехода,
дополнение имён и просмотр классов. Все четыре функции используют один индекс.

## Что берём из SETEdit

В SETEdit есть два разных механизма. `mainsrc/bufun.cc` ищет функции и
прототипы в текущем буфере, в том числе в несохранённых правках.
`mainsrc/tags.cc` читает проектный TAGS-файл: `Jump to symbol` открывает
единственное точное совпадение сразу, для нескольких показывает список,
запоминает прежнюю позицию и открывает файл определения. Этот же индекс
обслуживает word completion и Class Browser. Поведение и компоновка списков
полезны; парсер Exuberant Ctags, старые коллекции и shell-вызовы не переносим.

## Контракт этапа

- Индексируются существующие файлы из `Project::sources`, включая явно
  добавленные `.h/.hpp`; сборка уже отбирает из этого списка только
  компилируемые исходники. Без проекта индексируется сохранённый активный
  C/C++ файл. Несохранённый безымянный буфер не индексируется.
- Первый источник символов — Universal Ctags. Порядок поиска: явный путь из
  `TURBOIDE_CTAGS`, затем `ctags.exe` в `PATH`. Каждый кандидат проверяется
  на совместимость до запуска индексации; одного имени файла недостаточно.
  На рабочей машине локальная проверенная копия находится в
  `.deps/ctags-v6.1.0-x64/ctags.exe`, но этот путь не зашивается в продукт.
  Для разработки переменную можно направить на неё. В поставку IDE Ctags
  пока не включён.
- Ctags запускается как отдельный процесс без shell, с рабочей папкой
  проекта. Список файлов передаётся через временный `-L` файл, чтобы
  длинные пути и количество элементов не упирались в лимит командной строки.
  Вывод `-f -` читается из stdout; код выхода проверяется, stderr сохраняется
  для сообщения об ошибке (само наличие notice в stderr не означает сбой).
  Параметры `--options=NONE --excmd=number --fields=+n+i+Z` фиксируют формат
  с числовыми строками, областью видимости и наследованием. Временный файл
  удаляется после завершения, ошибки и отмены.
- Reader принимает только ожидаемые строки TAGS и валидный положительный
  номер строки, игнорирует псевдотеги, сохраняет дубликаты имён и разрешает
  относительный путь от каталога проекта. Для UI достаточно структуры
  `name/path/line/kind/scope/inherits`; regex-поиск и парсинг тела C/C++ не нужны.
- Индекс хранится в памяти для активного проекта. Перед запросом он
  перестраивается, если изменились состав файлов, размер или время записи
  любого индексируемого файла. При закрытии/смене проекта кэш очищается.
  Полная перестройка заменяет старый индекс целиком: удалённые и
  переименованные символы не остаются. Индекс не записывается в `.prj` или
  `.dsk`. Если генерация не удалась, показывается ошибка, а прежний индекс
  для изменённого набора файлов не выдаётся как актуальный.
- TAGS описывает файлы на диске. Для несохранённых правок UI сообщает, что
  результаты могут отставать; принудительного Save без запроса не делает.
  Парсер текущего буфера из `bufun.cc` в этот этап не входит.

## UI и порядок реализации

| Шаг | Поведение | Существующая точка подключения | Готово, когда |
| --- | --- | --- | --- |
| 1. Индекс | Команда по запросу строит индекс и различает отсутствие Ctags, отсутствие символов и ошибку обработки | `Project::sources`, Win32-подход к процессам из `src/build.cpp`, новый небольшой модуль индекса | На проекте с `.c/.cpp/.h` получены правильные имена, типы, файлы и строки; несовместимый Watcom Ctags отвергается |
| 2. Переход и возврат | `Search → Jump to symbol…` берёт C/C++ имя под курсором как начальный выбор; одно однозначное точное совпадение открывает сразу, иначе список показывает имя, тип, область, файл и строку. Enter переходит, Esc оставляет редактор. `Search → Back from symbol` возвращает файл и позицию | извлечение слова по образцу `identifierAtCursor()`; открытие и позиционирование по образцу `goToLocation()` в `src/main.cpp`; список по образцу `TListViewer` окон Project/Messages | Можно пройти через два файла, вернуться к исходному курсору, различить одноимённые определения; неудачный переход не записывается в историю, строка символа не подсвечивается как ошибка сборки |
| 3. Дополнение | `Search → Word completion` использует тот же индекс и существующий popup из `src/editor_features.cpp`; вставляет выбранное продолжение слова | открыть узкий доступ к локальному `chooseCompletion()` и использовать редакторский ввод | Один/несколько вариантов, Enter/Esc и undo работают; список не содержит дубликаты одинаковой вставки |
| 4. Браузер | `Search → Class browser` показывает классы/структуры, их члены и доступные связи родитель–потомок из `kind/scope/inherits`, с переходом к выбранному элементу | `TListViewer`, общий индекс и `goToLocation()` | Из класса можно открыть его член и вернуться; отсутствующие или неполные связи не создают ложную иерархию |

Первые две строки таблицы — минимальный работающий результат; дополнение и
браузер завершают этот этап после проверки общего индекса. Назначить
**Ctrl+F2** на `Jump to symbol`, как в SETEdit
(`reference/SetsEd/cfgfiles/menubind.smn`). Сейчас эта клавиша временно
назначена на **Stop debugging** в `src/main.cpp`; при добавлении перехода
убрать только её привязку к остановке, сохранив саму команду в меню Debug.
Восстановление исходного workflow отладки — отдельная задача; оно не должно
удерживать Ctrl+F2. Возврат должен быть отдельной командой, а не `Ctrl+Q P`,
уже занятой префиксными командами
редактора. История переходов — небольшой стек `{file, cursor offset}` в
памяти приложения; сохранение в `.dsk` не требуется. Текущий
`goToLocation()` после перехода ставит маркер диагностической строки:
для символов следует выделить из него общую операцию открытия/позиционирования
и оставить диагностический маркер только у переходов из Messages и отладчика.
Текущий `identifierAtCursor()` допускает `#` и `.` для Help и не читает
`::`; извлечение C/C++ имени для поиска и completion нужно проверить отдельно,
не меняя поведение Help.

Не смешивать список символов с диагностическими `BuildMessage`: они имеют
другое время жизни и поведение. Не добавлять LSP, базу данных, рекурсивное
сканирование каталога или отдельный framework completion. Не называть
переход семантическим `Go to definition`: Ctags индексирует имена, но не
разрешает перегрузки, макросы и тип выражения как компилятор.

## Проверка

1. Автоматически проверить reader на псевдотеге, пробелах и Unicode в пути,
   повторяющихся именах, отсутствующей строке и повреждённой записи; отдельно
   проверить полную перестройку после изменения и удаления файла. Тест
   использует маленький временный проект, без пользовательских `.prj/.dsk`.
2. Проверить локальный Universal Ctags и несовместимый Watcom Ctags;
   отсутствие инструмента должно оставлять редактирование и сборку рабочими.
3. Собрать `turboide` и штатные self-check по [AGENTS.md](AGENTS.md).
   В отдельном проекте в `%TEMP%` вручную пройти переход, неоднозначное имя,
   возврат, completion и браузер в классическом `conhost.exe`; проверить,
   что Ctrl+F2 вызывает переход, а Stop debugging доступен через меню;
   записать фактический хост и результат. После сохранения/удаления файла убедиться,
   что устаревших символов нет. Если меняется запуск процессов или экран,
   дополнительно проверить Run и debuggee по правилам `AGENTS.md`.

## Известные границы

Заголовки из одних лишь include-каталогов в первом варианте не попадают в
индекс: их можно добавить как элементы проекта без изменения сборки.
Числовые адреса требуют обновлять индекс после изменения файла на диске.
Большие проекты могут потребовать фоновой генерации, но сначала следует
измерить задержку на реальном проекте; не вводить поток и инкрементальный
`ctags -a` до такой проверки.
